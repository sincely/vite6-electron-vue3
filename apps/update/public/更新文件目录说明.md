# 更新文件目录说明

本目录是本地模拟 Electron 更新服务器的静态资源根目录，由 `http-server ./public` 对外提供服务。
`electron-update/` 下的内容是生成物（已被 `.gitignore` 忽略），不要手动修改，也不要提交到仓库。

## 目录结构

```text
apps/update/
├── package.json                  # sync / serve / start 脚本
├── scripts/sync.js               # 从 release/ 生成更新目录
└── public/
    ├── 更新文件目录说明.md        # 本说明
    └── electron-update/          # 更新服务根路径（访问地址 /electron-update/）
        ├── latest.yml                              # Windows 清单（win 打包产物生成）
        ├── lightning-win32-<版本>-Setup.exe
        ├── lightning-win32-<版本>-Setup.exe.blockmap
        ├── latest-mac.yml                          # macOS 清单（mac 打包产物生成）
        ├── lightning-darwin-<版本>-<arch>.zip       # mac 自动更新包（arm64 / x64）
        ├── lightning-darwin-<版本>-<arch>.zip.blockmap
        ├── lightning-darwin-<版本>-<arch>.dmg       # mac 手动安装包
        ├── lightning-darwin-<版本>-<arch>.dmg.blockmap
        └── update-config.json
```

## `electron-update/` 文件说明

| 文件                                    | 作用                                                                                                 |
| --------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `latest.yml`                            | 更新清单。`version` 为最新版本号；`path` / `files[].url` 为安装包文件名；`sha512` / `size` 用于校验    |
| `latest-mac.yml` / `latest-linux.yml`   | macOS / Linux 更新清单，结构与 `latest.yml` 相同；electron-updater 按客户端平台向同一 url 请求对应文件 |
| `lightning-darwin-<版本>-<arch>.zip`     | macOS 自动更新实际使用的安装包（mac 上只通过 `.zip` 安装，`.dmg` 仅供手动安装兜底）                  |
| `lightning-win32-<版本>-Setup.exe`      | 安装包。由 `release/<来源版本>/` 复制并按目标版本重命名，内容不变，所以 `sha512` 与原包一致           |
| `lightning-win32-<版本>-Setup.exe.blockmap` | 差量更新用的分块映射，缺失时会回退为全量下载                                                     |
| `update-config.json`                    | 远端更新配置（`eligible`、`disabledClientVersions`、`autoDownload`），应用每 2 分钟轮询一次           |

`update-config.json` 字段含义：

- `eligible`：为 `false` 时禁止检查更新
- `disabledClientVersions`：被禁用的版本列表，命中则强制升级，支持精确（`2.0.11`）与前缀（`2.0`）匹配
- `autoDownload`：是否发现新版本后自动下载

## 生成更新目录

`scripts/sync.js` 取 `release/` 下最新的构建产物，把版本号改高后复制到 `public/electron-update/`。

- 目标版本默认是 `max(根 package.json 版本, 来源版本)` 加一个 patch 号，保证高于开发环境当前版本
- 安装包只改文件名，内容不变，所以 `sha512` 和 `size` 不用重算
- 来源目录里有哪些清单就生成哪些（`latest.yml` / `latest-mac.yml` / `latest-linux.yml`），连同安装包、`.blockmap` 和默认的 `update-config.json` 一起写入，一次 sync 可产出多平台共用的更新目录
- 例如这次实际生成了 `2.0.12 -> 2.0.13`
- 可以用 `--from` 和 `--to` 指定版本，例如 `node scripts/sync.js --from 2.0.11 --to 2.0.20`
- 每次执行都会清空并重建 `electron-update/`，`public/` 下的其它文件不受影响

## 使用方式

在 `apps/update` 目录执行：

```bash
pnpm sync                                        # 生成更新目录（默认版本规则）
pnpm serve                                       # 启动静态服务（端口 8090）
pnpm start                                       # 先 sync 再 serve
node scripts/sync.js --from 2.0.11 --to 2.0.20   # 指定来源与目标版本
```

## 开发环境对接

根目录 `dev-app-update.yml` 指向本服务：

```yaml
provider: generic
url: http://127.0.0.1:8090/electron-update/
```

- 使用 `127.0.0.1` 而不是 `localhost`：本机 WSL / Docker 可能占用 IPv6 的同端口，`localhost` 会解析到 `::1` 而访问失败
- `dev-app-update.yml` 的端口必须与 `package.json` 中 `serve` 脚本的 `-p` 端口一致，`url` 末尾的 `/` 不能省略
- 开发环境只能验证到"检测到新版本"和"下载"，无法真正执行安装
- 更新检查仅在主窗口首次加载完成时触发一次，修改配置后需重启应用，或手动点击"检查更新"
- 开发环境日志不写文件，只输出到终端

## 使用事项

1. **先打包再生成**：`sync` 的来源是 `release/<版本>/`，需先执行 `pnpm run build-win:prod` / `pnpm run build-mac:prod` 等打包命令，目录中必须有对应平台的更新清单（`latest.yml` / `latest-mac.yml` / `latest-linux.yml`）和安装包，否则脚本会报错
2. **目标版本必须高于当前版本**：开发环境的当前版本取自根 `package.json`，服务端版本不高于它就只会提示"已是最新版本"
3. **每次重新打包后重新 `sync`**：生成物不会自动跟随 `release/` 更新，且 `sync` 会清空 `electron-update/`，手动放进去的文件会丢失
4. **改版本后无需重启服务**：静态服务直接读取磁盘文件，并已用 `-c-1` 关闭缓存，`sync` 后应用重新检查即可拿到新版本
5. **端口被占用**：报 `EADDRINUSE` 说明服务已在运行（或被 WSL / Docker 占用），先在原终端按 Ctrl+C 停止，或换端口，并同步修改 `dev-app-update.yml`
6. **仅用于本地测试**：不要把 `electron-update/` 下的安装包提交到仓库，也不要用它替代生产更新服务器；生产环境使用 `.env` 中 `VITE_UPDATE_URL` 配置的远程地址
7. **远端配置不走本地服务**：开发环境拉取 `update-config.json` 仍使用 `.env.development` 的 `VITE_UPDATE_URL`，该地址不可达时回退为默认配置（允许更新、不自动下载）；若要测试强制升级或禁止更新，需要让该地址可访问并修改其中的配置
8. **多平台支持**：脚本会处理来源目录中所有存在的清单（`latest.yml` / `latest-mac.yml` / `latest-linux.yml`），按客户端平台由 electron-updater 自行选择请求哪个。注意 macOS 自动更新用 `.zip` 安装，且真正执行安装（`quitAndInstall`）要求应用带有效签名（Squirrel.Mac 校验）；本地未签名打包在开发环境只能验证到"检测到新版本 / 下载完成"
